# Живой Хоринис: браузерный лаунчер Gothic II

Этот лаунчер запускает открытый движок OpenGothic/GothicDroid поверх локальных игровых файлов. Оригинальная игра в сборку не входит. Импорт папки использует файлы напрямую из выбора браузера. ZIP распаковывается в хранилище текущего браузера; его обработка, сохранения и настройки не отправляются на сервер.

## Локальный запуск

1. Выполнить `python serve.py` из этой папки и открыть <http://localhost:8000/> в Chrome или Edge на компьютере.
2. В Steam выбрать Gothic II: Gold Classic / Night of the Raven → «Управление → Просмотреть локальные файлы».
3. В лаунчере выбрать корневую папку игры, содержащую `Data` и `System`. Можно вместо неё выбрать ZIP; Windows-исполняемые файлы игнорируются. Игровые файлы читает открытый движок, а не исходный EXE.
4. Чтобы запустить сборку с локальным модом, поместить подготовленные `System/LivingKhorinis.ini` и `Data/ModVDF/LivingKhorinis.mod` в импортируемую копию папки (не обязательно изменять папку Steam). Для ванильного теста использовать адрес с `?vanilla=1`.
5. Сохранения этой браузерной сборки хранятся отдельно от Steam. Экспортировать через файловое меню до очистки данных сайта.

`dist` можно скопировать в подкаталог статического сайта, например `/game/`. Требуются HTTPS (либо localhost), полноценная вкладка, SharedArrayBuffer и WebGPU либо экспериментальный WebGL 2. Предпочтительны заголовки COOP `same-origin` и COEP `require-corp`; если сервер их не выставляет, локальный service worker пытается добавить их в своём подкаталоге. `serve.py` может обслужить и полный сайт: `python serve.py --directory /path/to/full-site`.

## Интеграция

Лаунчер подгружает `living-khorinis-hook.js` и вызывает `window.LivingKhorinisPrepare({ FS, gameRoot, Module })` после монтирования данных, до старта игры. Асинхронный результат `null` запускает ванильную Gothic II; `{ini: 'LivingKhorinis.ini'}` добавляет параметр `-game:LivingKhorinis.ini`. Готовый хук нативного адаптера поставляется в `dist`.

`python adapt.py` пересобирает HTML из закреплённого upstream shell. Происхождение WASM, лицензии и атрибуция перечислены в `dist/UPSTREAM.md`.

## Проверено

- Node: синтетические ZIP, включая вложенный корень и отсутствие игрового архива.
- Chromium: начальная страница, настоящая инициализация WASM, отдельная проверка статического сервера без COOP/COEP, восстановление после неправильного ZIP, отсутствие сторонних HTTP-запросов.
- Chromium: синтетическая папка и ZIP дошли до локальной файловой системы движка и вызвали мод-хук. Тестовые фикстуры не содержат оригинальную игру; реальное игровое меню, сохранение внутри игры и работу Daedalus-мода нужно проверить с настоящей установленной копией.

`node --test tests/import-worker.test.mjs` работает без Playwright. Для `tests/smoke-browser.cjs` и `tests/smoke-valid-local.cjs` нужен Chromium + Playwright и локальный сервер, адрес можно передать в `TEST_URL`.

## Сохранения и GitHub

В меню папки (под игровым экраном) есть скачивание сейвов и импорт. Архив не включает файлы установки. Импорт сохраняет оригинальный номер, если он свободен, либо использует свободный слот. Идентичные файлы в том же слоте пропускаются, внутренний слот 99 не переносится, при нехватке слотов план отклоняется до записи. Вход и перенос через GitHub ручные, без токена в лаунчере. См. `site/dist/saves.html`. Тесты после сборки адаптированного HTML: `node --test tests/saves.test.mjs`.
