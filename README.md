# Пепельная корона — Living World RPG

Запускаемая **расширенная alpha (мир v4)** single-player браузерной RPG по [исходному ТЗ](docs/MASTER_PROMPT.ru.txt).
Это первая рабочая вертикаль, **не полная реализация всех 20 разделов ТЗ**.
Точный объём и оставшиеся задачи: [STATUS.md](docs/STATUS.md).

## Быстрый запуск: Docker

Требуются Docker Engine/Desktop и Docker Compose v2. В Windows выполняйте команды в Ubuntu/WSL из каталога проекта.

```bash
cp .env.example .env
docker compose up --build -d
docker compose logs -f app
```

Откройте **http://localhost:3000**. Миграции выполняются автоматически после готовности PostgreSQL.
Нажмите «Начать новую историю», создайте героя, оставьте seed `ashen-crown` и нажмите «Войти в мир».
Необязательная команда `npm run db:seed` создаёт пустой начальный мир только при отсутствии автосохранения; для обычного запуска она не нужна.

Остановка: `docker compose down`. Данные остаются в томе `pgdata`.
**Не добавляйте `-v` к down**, если хотите сохранить игры.

## Первые действия в игре

1. «Войти в поселение» → примите контракт на волков → «Нанять 5 бойцов».
2. «Выступить против волков» → щёлкните по полю, чтобы направить бойцов; бой считается сервером в реальном времени.
3. После победы вернитесь, войдите в поселение и сдайте контракт через диалог или журнал. Выполненная охота сохраняется до получения награды, даже после следующих игровых дней.
4. Купите зерно; оно потребуется в путешествии. Выберите другое поселение на карте и нажмите «Отправиться».
5. Используйте ×1/×2/×5/×10. По умолчанию ×1 = один игровой день за секунду; в бою ускорение календаря отключено.
6. Откройте «Сохранения»: пять ручных слотов + автосохранение после игровых действий и завершения боя. Загрузка всегда ставит мир на паузу.

Пробел — пауза; E — вход в текущее поселение. Приказы, торговля и действия проверяются движком.
В стартовом мире 300 поселений и 18 000 отдельных жителей; герой и его родители добавляются при создании персонажа.
Начальная география не меняется от seed, политика и население воспроизводимы по seed.

## Разработка без Docker

Node.js **22.12+** (проверено на Node 24), npm.

```bash
cp .env.example .env
npm ci
npm run db:generate
```

В `.env` установите `STORAGE_DRIVER=file` и `PUBLIC_ORIGIN=http://localhost:5173`.
Файловый адаптер сохраняет тот же полный снимок мира, что и PostgreSQL.

```bash
npm run dev
```

Клиент: http://localhost:5173; сервер: http://localhost:3000. Vite проксирует `/api` и `/ws`.
Пакет движка автоматически пересобирается, сервер перезапускается при изменении собственного кода.
После изменения движка перезапустите сервер, если его watcher не заметил обновление зависимого пакета.

### Разработка с PostgreSQL

```bash
docker compose up -d db
```

В `.env`: `STORAGE_DRIVER=postgres`, `DATABASE_URL` из примера (с вашим паролем), `PUBLIC_ORIGIN=http://localhost:5173`.

```bash
npm run db:migrate
npm run dev
```

### Собранное приложение без Docker

В `.env` установите `PUBLIC_ORIGIN=http://localhost:3000`. Если PostgreSQL не запущен, используйте `STORAGE_DRIVER=file`.

```bash
npm run build
npm start
```

## OpenRouter (необязательно)

```dotenv
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=openai/gpt-4.1-mini
```

Перезапустите сервер (в Docker: `docker compose up -d --force-recreate app`).
Затем в игре: **Диагностика → Включить AI Director → Сохранить настройки**.
По умолчанию AI выключен; максимум 10 запросов на мир, интервал 30 игровых дней.
Поддержка structured outputs зависит от выбранной модели/провайдера; неподдерживаемый ответ отклоняется и попадает в журнал.
Ключ не передаётся клиенту и не записывается в сохранение.

Director отправляет только ограниченный контекст исторических событий и получает JSON proposal.
В первой версии он запрашивает субъективные хроники. Движок также имеет валидаторы `assign_nickname` и `spawn_quest`, которые можно подключить к расширенному Director.
Ни недоступный API, ни ошибочный ответ не останавливают симуляцию.
Схема интеграции сверена с [документацией OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs).

## Linux deployment

1. Установите Docker/Compose, скопируйте проект или клонируйте репозиторий.
2. Создайте `.env`. Задайте уникальные `POSTGRES_PASSWORD`, `GAME_PASSWORD`, `PUBLIC_ORIGIN=https://your-game.example`.
   Для пароля PostgreSQL в URL используйте URL-safe символы, например шестнадцатеричную строку.
3. Выполните `docker compose up --build -d`.
4. Настройте HTTPS reverse proxy (Caddy/Nginx/Traefik) на `127.0.0.1:3000`, с поддержкой WebSocket.
   Compose по умолчанию публикует порт только на localhost.
5. Откройте свой домен и войдите с `GAME_PASSWORD`.

Один экземпляр приложения = один общий мир. Это single-player сервер, не многопользовательский сервис.
Не запускайте несколько экземпляров backend для одной БД: активная симуляция находится в памяти процесса.
При обновлении выполните `docker compose up --build -d`; остановка сохраняет мир в слот 0.

Резервная копия:

```bash
docker compose exec -T db pg_dump -U rpg -d rpg > rpg-backup.sql
```

## Игровые действия после доработки

- **Разговоры:** нажмите на взрослого жителя в сцене поселения или «Поговорить» в карточке. Реплики берутся из состояния мира. Через разговор можно принять и сдать реальный контракт, перейти к рынку или отряду, найти работу.
- **Постой:** день отдыха стоит 5 монет за героя + 1 за каждого бойца. Нужна еда; проходит настоящий игровой день. Лечит героя и выживших спутников, эффективность зависит от медицины.
- **Работа:** поле — 10 монет, кузница — 16. Оплачивает казна поселения, создаются товары, кузница тратит железо и дерево. За действие проходит день.
- **Отряд:** отдельный раздел с именами/ID, здоровьем, опытом, моралью и пайками. Зерно расходуется из ваших запасов, а не бесплатно берётся на рынке. Автопополнение оставляет герою 3 зерна.
- **Обучение:** весь отряд можно обучить как пехоту, копейщиков, лучников или конницу. Последняя требует лошадь на бойца; лошади погибших теряются. Классы влияют на дальность, урон и скорость боя. Смешанные формирования и маги пока не реализованы.
- **Приказы:** атака преследует противника; удержание останавливает движение и допускает атаку в пределах дальности; щелчок по полю задаёт точку движения. Все 60 бойцов и герой размещаются внутри поля.
- **Задания:** журнал показывает принятые и выполненные контракты. Можно найти место на карте и отказаться от невыполненного задания в поселении.
- **Путешествия:** поиск поселений, оценка длительности/расхода еды, пауза по прибытии или блокировке пути.
- **Сохранения:** формат v4, автоматическая миграция v1/v2/v3 при загрузке. Новый снимок не следует открывать старой версией приложения. Ошибка автосохранения отображается отдельно от результата уже выполненного действия.

## Что проверить после обновления

1. Загрузить существующий слот v1, сохранить его в свободный ручной слот.
2. Создать новый мир, войти в стартовое поселение, открыть разговор с жителем.
3. Принять охоту, набрать 5 бойцов, купить зерно, проверить раздел «Отряд».
4. Провести бой, проверить приказы, вернуться, отдохнуть и получить награду через разговор.
5. Поработать день, проверить деньги и календарь; переобучить отряд в лучников.
6. Найти соседнее поселение, отправиться туда, проверить паузу по прибытии.
7. Сохранить/загрузить, сверить инвентарь, бойцов и журнал заданий.
8. Проверить интерфейс на компьютере и телефоне. Интерактивная визуальная проверка в среде разработки не выполнена.

Локальные сборка, Prisma generate, форматирование и 28 тестов пройдены. GitHub Actions для этой серии коммитов намеренно пропускается по запросу владельца (`[skip ci]`). PostgreSQL/Docker и браузерную приёмку следует выполнить на целевом окружении.

### Местная власть

Войдите в поселение и откройте «Державы» → совет. За контракты, помощь при голоде и личное строительство растёт местная репутация. При репутации 40 и пяти бойцах можно получить признание защитником. При репутации 60, лояльности не ниже 50 и отсутствии затяжного голода совет выдаёт мандат управляющего.

Управляющий устанавливает местный сбор 0–20% и строит из общественных материалов и казны. Деньги на строительство получают реальные работники; личный кошелёк остаётся отдельным. Общая налоговая нагрузка выше 20% снижает лояльность. Если она не превышает 25 четырнадцать дней подряд, совет отзывает мандат. После отзыва или отставки новое назначение недоступно 30 дней. Должность не наследуется.

Для ручной приёмки проверьте назначение, изменение сбора, расход материалов и казны, сохранение/загрузку мандата, затем отставку и отказ в действиях без полномочий. Остальная политическая карьера отмечена незавершённой в `docs/STATUS.md`.

### Расширенный игровой цикл

Откройте **«Жизнь и власть»**: там находятся владения, учёба, семья, областная карьера, дипломатия, походы и осады. Основные действия проверяются сервером; получение почётного титула не заменяет полномочий.

- **Владение:** заработать 400 монет → купить ферму/шахту/мастерскую → пополнять кассу на зарплаты → забирать фактически произведённые товары → продать на рынке.
- **Династия:** подарки местному NPC (20 монет, +5 доверия раз в день) → признание при доверии 10 (50 монет). После смерти выбрать взрослого наследника; имущество разделяется по закону, а навыки нового героя остаются его собственными.
- **Власть:** мандаты с лояльностью 50 в половине поселений области → назначение в областном центре. Большинство областей, 10 бойцов и легитимность 40 позволяют заявить верховные притязания в столице. Наследственная династия должна находиться в кризисе; выборные формы проводят голосование.
- **Осада:** объявленная война с обоснованной претензией → прибытие к чужому поселению с пятью бойцами → блокада. Нужна своя еда; можно ждать капитуляции или штурмовать реальный гарнизон. Для выхода снять осаду.
- **Магия:** найти в областном городе живого учителя → 60 монет и три дня на школу → в бою выбрать заклинание и цель. Нужен врождённый потенциал; радиус 8, цена 10 маны. Индивидуальное обучение бойцов доступно в «Отряде».
- **Охрана:** выбрать находящийся рядом существующий караван с опасным маршрутом. Не менее трёх бойцов. Награда 30 монет резервируется отправителем и платится после доставки.
