1. КОНЦЕПЦИЯ И SOURCE OF TRUTH
Игра сочетает живой мир масштаба WorldBox, путь героя/правителя в духе Mount & Blade и управление отрядами в духе Heroes of Might and Magic, но с real-time боями. Игрок — физическая сущность мира, а не центр симуляции. Мир потенциально бесконечен. Получение короны не включает отдельный стратегический режим: игра всегда остаётся RPG.

Simulation Engine — единственный source of truth. React, Phaser, UI, OpenRouter и narrative layer не изменяют мир напрямую. Все изменения проходят через Simulation Command + Validator. Simulation Engine — отдельный TypeScript-модуль без зависимости от React, Phaser или OpenRouter.
AI pipeline: Simulation -> Event Detection -> Context Builder -> OpenRouter -> Structured Proposal -> Validator -> Simulation Command -> Result -> Historical Memory.
При недоступности OpenRouter игра продолжает работать.

2. СТЕК
TypeScript; React для HUD/меню/admin; Phaser 3 для 2D изометрии; Node.js + TypeScript backend; PostgreSQL; Prisma; WebSocket там, где нужен live state; Docker Compose; Vitest. OpenRouter API key только backend-side в .env. Модель выбирается через config/admin.

3. КАРТА, СЦЕНЫ И ВРЕМЯ
География одного континента фиксированная и не procedural при New Game. Биомы/ландшафт влияют на ресурсы, урожай, перемещение, логистику, сезоны и войну.

На старте 10 государств. Их названия, формы правления, идеологии, расы, символика, история и отношения генерирует обычный Simulation Engine по RNG seed без LLM. Seed воспроизводит стартовый политический мир.

Масштаб: 10 государств; 4–8 областей на государство; область всегда имеет центральный город; обычно 3–8 деревень; ориентир 250–400 поселений; население может составлять миллионы Population Entity. Нейтральных территорий нет. Граница определяется контролируемыми объектами. Континент и государства известны в общих чертах, детали открываются при посещении. Захват центра области даёт другим поселениям время сопротивления. Есть замки; обязательных подземелий нет. Можно строить поселения, дороги, мосты, замки и шахты. Дороги также развиваются из торговли.

Три Phaser scenes: World Scene, Settlement Scene, Battle Scene. Поселение и бой загружаются отдельными 2D сценами. Управление point-and-click + hotkeys.
Расстояния: соседние деревни 1–3 игровых дня; область 5–15 дней; государство несколько недель.
Время: pause/x1/x2/x5/x10. Есть абсолютные дни/месяцы/годы и сезоны. Государства могут иметь свои календари/эпохи. Сезоны влияют на экономику, урожай, движение, снабжение, болезни и войны. Игрок может ждать годы; долгоживущие расы видят смену поколений.

4. НАСЕЛЕНИЕ, РАСЫ И НАСЛЕДОВАНИЕ
Каждый житель существует в симуляции, но используй два уровня.
Population Entity: stable ID, родители/дети, ancestry, пол, дата рождения/возраст, alive/dead, здоровье, профессия, location/settlement, социальный статус, базовое имущество, государственная принадлежность, военная служба и компактные параметры.
Full NPC: всё выше плюс имя, биография, character traits, отношения, память значимых событий, персональная история, титулы, должности, притязания, репутационные связи и нужный инвентарь. Встреченный или ставший значимым человек может быть promoted в Full NPC и не теряет историю. Кузнец может естественно стать солдатом, генералом, мятежником или королём.

Базовые цивилизованные расы: Human, Elf, Dark Elf, Orc, Dwarf, Goblin. Все могут скрещиваться. Храни ancestry как пропорции, а не enum каждой смеси. Display race определяется доминирующим/смешанным происхождением; параметры — ancestry + индивидуальная вариативность. У рас различаются lifespan, maturation, fertility, health, strength, agility/speed, recovery, magical potential. Врождённой политической ненависти рас нет; дискриминация определяется государством. Undead — состояние/трансформация представителя любой расы.

NPC и игрок стареют, рождают детей и умирают. Игрок может вступить в брак. После смерти продолжение только за одного допустимого кровного или признанного наследника; без наследника game over. При нескольких детях имущество распределяется по законам наследования; выбранный наследник получает свою долю, частичное репутационное наследие и притязания. Остальные дети остаются NPC.

5. ПОСЕЛЕНИЯ, ЭКОНОМИКА И ЛОГИСТИКА
Поселения эволюционируют: settlement -> village -> large village -> town/city -> large city. Рост зависит от населения, еды, безопасности, торговли, инфраструктуры и ресурсов. Возможна деградация до руин. Новые поселения возникают из миграции и экономики. Население приблизительно реалистичное.

Экономика НЕ random gold. Обязательный data flow: population -> professions -> production -> local storage -> consumption -> surplus/deficit -> prices -> trade/transport -> destination storage.
Ресурсы физически локализованы: еда/зерно, мясо/рыба при необходимости, дерево, камень, железо, драгоценные металлы, ткань/шерсть/кожа, лошади, инструменты, оружие и расширяемый список. Не все государства имеют всё. Есть реальные склады и запасы. Деньги подробно учитываются для игрока, государства, рынков и значимых организаций, но не нужна бухгалтерия каждой мелкой транзакции миллионов NPC. Есть частная собственность. Рынок динамический.

Товары реально перевозятся караванами. Караван существует на карте и может быть ограблен, уничтожен, защищён или сопровождаем. Перерезанный маршрут прекращает поставки. Армии требуют еды, оружия, лошадей и пополнения; без логистики голодают и дезертируют.
Жители имеют профессии. Призванный солдат перестаёт быть гражданским рабочим. Массовые военные потери создают реальную демографическую яму.

6. ГОСУДАРСТВА, ПОЛИТИКА И ДИПЛОМАТИЯ
Базовый скелет — вассально-феодальная иерархия: верховный правитель -> крупные вассалы/области -> локальные лорды/города -> деревни.
Формы правления меняют титулы, легитимность, наследование, ритуалы, идеологические бонусы, законы и поведение, но используют общий движок. Поддержи абсолютную/феодальную/выборную монархию, республику, торговую республику, теократию, племенную конфедерацию, военную диктатуру, совет знати, магократию и расширяемые формы. Форма может эволюционировать. Государства могут исчезать, раскалываться и возникать заново.

Идеология — набор общественно-политических вех/доктрин, влияющих на бонусы, налоги, права рас, религию и решения. Чрезмерное изъятие ресурсов, дискриминация, реформы, поражения и кризисы снижают лояльность/легитимность и способны вызвать восстание.
Правитель — физический NPC. Убийство запускает наследование/передел власти; убийца не становится автоматически королём. Налоги идут по цепочке producer/settlement -> local lord -> regional lord -> sovereign.

Дипломатия: war, peace, alliance, trade agreement, vassalage, guarantee, truce, tribute, military access и расширяемые договоры. Отношения имеют основание: religious alliance, trade alliance, territorial war, holy war, rebellion, succession conflict и т.д. Нет обязательных гонцов и отдельного шпионажа. Династический брак создаёт притязания, но не автоматическое право. Государства хранят историческую память. Есть territorial claims. Федераций нет — только союзы.

Государства анализируют ресурсы и стратегию, но personality правителя и идеология могут перевесить экономическую рациональность. Серьёзное политическое решение должно иметь внутримировое обоснование/casus belli. Не делай войны простым random event.

7. ВОЙНА И BATTLE SCENE
Армии формируются из реальных жителей. Солдаты сохраняют идентичность; выживший возвращается тем же NPC/Population Entity. Есть опыт и карьерный рост.
Классы/контр-система: infantry, spearmen, archers, cavalry, mages, siege units и расширяемые типы. Расовые параметры влияют на конкретных бойцов.

Есть осады. Город использует реальные запасы; голод снижает здоровье/мораль и способен вызвать капитуляцию/мятеж. Город можно взять штурмом, переговорами, капитуляцией или внутренним бунтом. Fog of war не нужен. Разграбление, рабство, массовые потери и разрушение отражаются в демографии, экономике, отношениях и истории.

Battle Scene — 2D изометрический real-time tactical combat. Игрок командует отрядами (например 40 spearmen / 25 archers / 8 cavalry / 2 mages) и присутствует на поле как отдельный персонаж. Итог возвращает конкретные потери, ранения и состояние ресурсов в Simulation Engine.

8. МАГИЯ, РЕЛИГИЯ И МОНСТРЫ
Магия редкая, но чрезвычайно сильная. Magical potential — редкая наследуемая характеристика с небольшой случайной вариативностью. Потенциал не равен умению: требуется обучение. Сильнейший маг способен изменить исход крупного сражения, но физически уязвим.
Поддержи расширяемые школы: elemental, healing, nature, illusion, necromancy, summoning, spatial и другие. Государства заинтересованы в сильных магах. Маг может стать лордом/правителем; магократия может возникнуть естественно. Есть редкие магические ресурсы и исторические артефакты.

Религия — социальная система верований и не обязана иметь бога. Разные расы могут исповедовать одну религию. Религии/течения способны возникать исторически.

Есть монстры: волки, пауки, тролли, драконы, нежить и т.п. Популяции размножаются, мигрируют, создают логова и влияют на торговлю/демографию. Уникальные разумные существа могут иметь имя, возраст, память и жить сотни лет; с ними возможно договориться. Допускается приручение подходящих существ. Есть редкие природные и магические кризисы с реальными последствиями.

9. RPG И ПУТЬ К ВЛАСТИ
Создание героя в духе Mount & Blade: раса -> пол -> родители/происхождение -> место рождения -> детство -> подростковый период -> обучение/профессия -> важное событие -> причина путешествия. Выборы меняют характеристики, навыки, имущество, связи, репутацию и стартовую точку. Допускается рождение внутри существующей семьи симуляции.

Характеристики: Strength, Agility, Endurance, Intelligence, Charisma, Willpower, Magical Potential. Навыки: weapons/melee, archery, riding, command, trade, diplomacy, medicine, crafting/smithing, stealth, magic, governance и расширяемые. Нет уровней; навыки растут использованием. Есть RPG inventory.

Репутация хранится отдельно для деревни, города, области, государства, NPC и организаций. Не вводи универсальное Influence число: влияние следует из собственности, титула, армии, репутации, гильдии, советнической позиции и отношений.

Есть legitimacy. Основания власти: наследование, признание лордов, выборы, завоевание, религиозное/идеологическое признание, революция и правила формы правления.

Игрок может стать владельцем, лордом, правителем области, верховным правителем, основать династию, перейти к врагу или потерять власть и продолжить игру. Новое государство можно основать, захватив город либо создав достаточное идеологическое обоснование.
Игрок может не становиться правителем: торговец, маг, генерал, религиозный лидер, разбойник и т.п. Для системного политического влияния он должен создать/возглавить организацию либо стать советником/кукловодом.

Правитель-игрок управляет налогами, законами, армией, назначениями, экономикой, строительством, религией, правами рас, дипломатией и торговлей. Он может менять название, герб, флаг, цвет, титулы, форму правления, идеологию и законы. Непринятые реформы снижают легитимность и могут привести к гражданской войне.

10. NPC, КВЕСТЫ И АРТЕФАКТЫ
Full NPC имеют отношения, character traits и память значимых событий. Traits реально влияют на решения и могут меняться. Не используй LLM для обычных диалогов: они системные/шаблонные. Игрок воздействует на мир игровыми действиями и выбираемыми репликами, а не прямыми промтами World Director.

Главный принцип квестов: проблема мира существует раньше квеста. Problem -> need -> quest. Монстр реально нападает -> появляется контракт; не хватает еды -> поставка; бандиты реально действуют -> задание. Типы: kill, find, deliver, escort, defend, talk, capture, build, train и расширяемые.
Квест может перерасти в emergent цепочку, завершиться без игрока, если проблему решил другой NPC, и быть провален без game over. Допускаются неожиданные системные решения, например нанять бандитов вместо убийства.

Предметы имеют историю. Обычный меч может постфактум стать легендарным, если реально участвовал в значимых событиях.

11. OPENROUTER WORLD DIRECTOR
OpenRouter НЕ симулирует мир. Он применяется только для редких эпических событий, исторического narrative, легенд, названий и квестовых цепочек.

Три уровня событий:
1. Simulation Event — механический факт.
2. Historical Event — Event Detector определил значимость.
3. Narrative Event — OpenRouter связывает подтверждённые факты в историю.

OpenRouter не имеет прямого доступа к БД и не меняет числа. Он получает ограниченный структурированный JSON и возвращает JSON по строгой schema с proposal. Validator проверяет proposal.

Разрешённые предложения должны быть whitelist-командами вроде create_claim, propose_war, spawn_quest, assign_nickname, create_historical_title, propose_policy, create_organization, create_religious_or_ideological_movement. Simulation Engine принимает или отклоняет их.

AI не переписывает объективное прошлое. Если короля убил волк, нельзя объявить тайное убийство объективным фактом. Но субъективные слухи могут быть ложными. Храни objective history отдельно от chronicles/rumors/beliefs.

AI может постфактум давать имена эпохам, войнам, предметам и историческим NPC на основании реальных событий. Может создавать хроники/книги, которые существуют как предметы и могут быть предвзятыми или ошибочными.

AI Director имеет право РЕДКО инициировать внешний импульс/кризис, чтобы мир не становился навсегда статичным. Используй cooldown, rarity, world-state constraints и event budget. После импульса все последствия снова считает Simulation Engine.

12. ЖИВОЙ МИР И ПРИЧИННОСТЬ
Базовая симуляция должна работать без LLM: рождения, смерти, миграция, профессии, производство, потребление, рынки, караваны, строительство, рост/упадок поселений, политика, войны, дипломатия, смена правителей, восстания, монстры и экология.

Примеры причинных цепочек:
resource extraction -> local shortage -> discontent -> lord relations -> legitimacy drop -> split -> demands -> rebellion -> civil war.
monster population -> attacks -> caravan losses -> food shortage -> price rise -> settlement quest -> military response.
war casualties -> workforce loss -> production decline -> tax decline -> military weakness -> political instability.

Квест НЕ создаёт проблему. Проблема создаёт квест.
Легенда НЕ создаёт событие. Событие создаёт легенду.

13. СОХРАНЕНИЯ И DETERMINISM
Сделай 5 save slots + autosave.
Сохраняется полное состояние мира: player, population, genealogy, states, settlements, ownership, economy, stocks, caravans, armies, wars, diplomacy, items, quests, historical events, destroyed states, AI events и RNG state.

Seed + deterministic RNG должны позволять воспроизводить стартовый мир и поддерживать deterministic simulation tests там, где это возможно.

14. ПРОИЗВОДИТЕЛЬНОСТЬ
Миллионы жителей нельзя каждый tick обрабатывать как Full NPC. Используй batching, aggregate scheduling, event queues, spatial partitioning, coarse simulation для далёких систем и promotion/demotion detail levels, не нарушая идентичность Population Entity.

Не рендери всё население мира. Settlement Scene материализует только релевантных NPC.

Simulation tick rate должен быть отделён от render FPS. Time acceleration не должна требовать пропорционально большего количества render frames.

Добавь performance benchmark/test для симуляции большого мира.

15. ADMIN И OBSERVABILITY
Сделай простую backend/admin страницу, без требования красивого дизайна. Нужны:
- просмотр текущего world state;
- просмотр Simulation Events / Historical Events;
- OpenRouter request/response logs;
- accepted/rejected AI proposals и причина rejection;
- выбор OpenRouter model;
- включение/отключение AI Director;
- базовые параметры частоты/лимитов AI;
- диагностическая информация simulation tick/performance.

16. ВИЗУАЛЬНЫЙ СТИЛЬ
Полностью 2D. Минимальная графика допустима: простые тайлы, геометрические фигурки/кубики, простые sprites/placeholders. Не трать основную разработку на artwork.

UI и экраны стилизуй под dark fantasy: читаемые панели, рамки, гербы/цвета государств, исторический журнал. Gameplay readability важнее декоративности.

После каждой фазы запускай tests/build и исправляй ошибки перед продолжением.

18. DEFINITION OF DONE
Работа не считается завершённой только потому, что приложение открывается.

Минимальный итог должен позволять:
- docker compose up поднять систему;
- создать New Game с seed;
- увидеть фиксированный континент и 10 сгенерированных государств;
- создать персонажа через biography flow;
- перемещаться по карте мышью;
- входить в поселения;
- видеть реальные данные населения/ресурсов;
- наблюдать производство, потребление и изменение запасов;
- видеть реальные караваны и изменение запасов после доставки/потери;
- наблюдать автономное развитие мира при ускорении времени;
- видеть рождения, смерти и смену поколений;
- наблюдать изменение поселений;
- видеть политические отношения, войны и смену правителей;
- сформировать/получить отряд;
- запустить real-time Battle Scene и вернуть последствия в мир;
- получить хотя бы несколько квестов, возникших из реального world state;
- иметь reputation/legitimacy/political progression;
- сохранять и загружать полный мир;
- продолжать играть при отключённом OpenRouter;
- при настроенном OpenRouter получать структурированные narrative proposals и видеть их validation/logging;
- иметь tests для ключевой причинности и determinism;
- иметь README с точными командами установки, запуска, тестирования, настройки OpenRouter и deployment.

19. ЗАПРЕЩЁННЫЕ УПРОЩЕНИЯ
Нельзя выдавать статичную карту с фальшивыми цифрами за симуляцию.
Нельзя хранить население только одним числом, потому что жители должны иметь идентичность, семьи и становиться историческими NPC.
Нельзя телепортировать ресурсы между поселениями.
Нельзя создавать армии из абстрактного manpower без связи с населением.
Нельзя генерировать войны чистым random без причин.
Нельзя создавать квестовую проблему только после принятия квеста.
Нельзя позволять LLM напрямую писать в БД или произвольно менять world state.
Нельзя делать LLM обязательным для работы игры.
Нельзя заменять Battle Scene простым random-result диалогом.
Нельзя после получения власти превращать игру в отдельную глобальную стратегию.
Нельзя считать задачу выполненной после создания архитектуры без рабочего вертикального gameplay loop.

20. ФИНАЛЬНАЯ ПРОВЕРКА
Перед завершением самостоятельно:
- запусти install/build/test;
- подними Docker Compose;
- примени migrations;
- создай новый мир;
- выполни smoke test основного gameplay loop;
- проверь save/load;
- проверь работу без OpenRouter;
- проверь mock/test OpenRouter structured response;
- проверь отсутствие секретов в репозитории;
- проверь README с командами deployment;
- исправь найденные ошибки.

После этого дай краткий итог: что реализовано, архитектура, как запустить, где задать OPENROUTER_API_KEY, какие команды tests/build/deploy использовать и какие сознательно оставленные расширения не блокируют основной gameplay.
