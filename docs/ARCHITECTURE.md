# Архитектура alpha 0.1

## Граница ответственности

React/Phaser → JSON command → серверная Zod schema → доменные проверки → Simulation Engine → World → WebSocket projection.

Движок — TypeScript-пакет без React, Phaser, HTTP, БД или LLM. Клиент не присылает итог боя, баланс денег или новый state.
Сервер обрабатывает команды и календарные шаги последовательно. New Game создаёт новый мир отдельно и заменяет активный мир только после успешного автосохранения.

## Время и случайность

- Xorshift32; hash строкового seed; состояние RNG сохраняется.
- Внутри движка нет Date.now/Math.random и системного времени.
- Мир обрабатывается раз в секунду; ×N вызывает N дискретных дней.
- Бой обрабатывается фиксированным шагом 250 мс независимо от render FPS, календарь на это время остановлен.
- Replay гарантирован для одинакового seed, последовательности команд, числа дней и шагов боя. Ответ внешней LLM сам по себе недетерминирован, но результат хранится в снимке.

## Население

Индекс в `people` — неизменный ID. Погибший не удаляется и ID не переиспользуется.
Семья хранит двусторонние ссылки родители/дети; ancestry — шесть долей, ребёнок наследует среднее родителей.
`npcs` хранит дополнительную детализацию только значимых/встреченных жителей.
У поселений есть индексы жителей и агрегаты профессий. Производство использует агрегаты.
Демография обрабатывает одну из 30 детерминированных групп жителей за день.
Голод воздействует на здоровье в этой же месячной группе. Это осознанное сглаживание, а не ежедневная проверка каждого жителя.

## Причинность

- Профессии → производство → физические запасы → потребление → дефицит → цены и лояльность.
- При отправке каравана груз снимается со склада; получатель платит отправителю. Прибытие добавляет груз один раз. Утрата уничтожает груз, оплата не возвращается.
- Караваны идут по графу дорог с длительностью рёбер. Заблокированная дорога останавливает движение.
- Набор солдата сохраняет его ID, выводит из прежней профессии, расходует оружие/еду поселения. Демобилизация возвращает прежнюю профессию.
- Недостаток армейской еды → падение морали → дезертирство тех же личностей.
- Долгий дефицит + богатый соседний объект + доступный набор → обоснованная пограничная война. Потери берутся из реальных наборов.
- Войны alpha — небольшие приграничные столкновения; полноценный стратегический AI кампаний ещё не реализован.
- Квесты еды/волков возникают из существующих shortageDays/monster population. Принятие контракта не создаёт проблему.

Налоговый доход вычисляется из стоимости произведённого зерна и распределяется 35% поселению, 30% области, 35% государству.
Это упрощённая монетизация натурального дохода, не замкнутая макроэкономическая модель денежной массы. Торговые сделки сохраняют деньги между участвующими счетами.

## Сохранения

PostgreSQL/Prisma хранит шесть строк SaveSlot: 0 autosave, 1–5 manual.
Каждая строка содержит gzip-представление полного World + SHA-256 исходного JSON + seed/day/schema version.
Такой снимок сохраняет граф личностей и RNG без сложной частичной синхронизации тысяч таблиц.
Файловый адаптер для разработки имеет тот же формат, atomic rename и контрольную сумму.
Миграция относится к таблице SaveSlot; при изменении формата World нужна отдельная миграция снимков, а не только Prisma migration.

Отдельная нормализованная БД населения и инкрементальные снимки — следующий этап при реальной длительной симуляции миллионов людей.

## OpenRouter

Event detector реализован как историческая значимость доменных событий.
Director выбирает последние подтверждённые события, ограничивает контекст, частоту и число обращений.
AI возвращает строго структурированную хронику; локальный whitelist перепроверяет формат и ссылки на факты.
Хроники помечаются `subjective: true`, лежат отдельно от объективных событий и не меняют их.
Историческая ссылка доказывает наличие основания, но не семантическую истинность каждого предложения LLM; поэтому хроника никогда не объявляется объективной историей.
Ответ от старого мира после New Game/Load игнорируется.

## Доступ

При GAME_PASSWORD сервер выдаёт HttpOnly SameSite cookie; при HTTPS добавляет Secure.
HTTP API и WebSocket требуют этой сессии. Origin проверяется для запросов браузера.
Вход ограничен десятью попытками в минуту на IP. Это минимальный доступ к личному single-player серверу, не полноценная система аккаунтов.
Проверка роли отдельного admin отсутствует: владелец игры имеет доступ к admin.
Секрет OpenRouter не входит в WebSocket projection, БД сохранений или журнал запросов.

## Игровые сервисы и снимки v2

`POST /api/dialogue` принимает ID доступного взрослого жителя. Команда `talk` проверяет сцену и локацию, материализует NPC и один раз записывает знакомство. Реплики и варианты формируются функцией `conversation` по реальным запасам, угрозам и контрактам. Вариант с действием отправляет обычную доменную команду, не отдельный обход валидации.

Отдых и работа продвигают общую симуляцию через `tickDay`, после чего ставят её на паузу. Оплата перемещается между казной и героем. Игрок снабжает отряд из своего инвентаря; запас армии и запас героя не складываются в абстрактный счётчик.

Снимок v2 добавляет `Army.mounts`, `Quest.objectiveMet`, `Fighter.order`. Поля опциональны в типах для совместимого чтения данных и определены по умолчанию. При загрузке v1 хранилище проверяет исходную checksum, затем переводит снимок в v2: конница без учтённых лошадей получает 0, старые приказы трактуются как движение, принятая охота с нулевой текущей угрозой отмечается выполненной. Сохранение всегда пишет текущую версию мира.

Успешные действия, кроме частых тактических приказов и переключения скорости, сохраняются в слот 0. Результат боя тоже сохраняется. Если запись после команды не удалась, команда не сообщается как неудачная: мир уже изменён; возвращается отдельное предупреждение saveError. Это предотвращает повтор покупки из-за ошибки записи снимка.

## Местное управление и снимки v3

`Settlement.governance` хранит ID управляющего, дополнительный местный сбор, последовательные дни недоверия и дату следующего допустимого назначения. Полномочия проверяются по ID действующего лица, не строке титула. Все действия требуют живого героя внутри своего текущего поселения, без путешествия или боя.

Назначение требует репутации 60, ранее полученного местного титула защитника, пяти бойцов, лояльности 50 и менее трёх дней дефицита. Местный сбор 0–20% добавляется к государственной ставке только при расчёте нагрузки на лояльность; весь доход этого сбора остаётся поселению. Старая государственная налоговая цепочка сохраняется.

`public_build` расходует 100 дерева, 50 камня и 200 монет поселения, делит оплату между живыми взрослыми гражданскими работниками и повышает инфраструктуру до предела 10. `relief` перемещает личное зерно на склад; репутация и лояльность начисляются только за закрытый дефицит суточного гражданского потребления. Повторное дарение на полный склад не создаёт поддержку.

Ежедневно после экономики `localGovernance` отзывает мандат после 14 подряд дней лояльности ≤ 25, либо смерти управляющего. Отставка использует тот же путь: удалить действующий титул, отменить местный сбор, закрыть повторное назначение на 30 дней, записать историческое событие. Отзыв не убивает героя и не завершает игру.

Миграция v2 → v3 добавляет каждому поселению пустой мандат и нулевые сбор/недоверие/ожидание; RNG и почётные титулы сохраняются. v1 проходит обе миграции. Все 10 форм правления пока разделяют эту локальную процедуру; государственные выборы и региональные должности остаются следующим этапом.

## Расширение v4

- `polity.ts`: правила правления, наследование/голосование, областные руководители, передача объектов и отделение недовольной области. Право управлять проверяется по ID должности; строки титулов не являются разрешениями.
- `campaign.ts`: движение государственных армий, состояние осады, блокировки дорог, голод гарнизона, капитуляция и снятие осады. `combat.ts` принимает реальную вражескую армию; её живые/погибшие бойцы возвращаются в симуляцию. Исчезнувшие державы остаются в истории с `capital = -1`.
- `property.ts`: из измеренного ежедневного выпуска до общественного потребления выделяется доля оплаченных работников. Это перенос товара между складами, не второе производство. Доли владений и NPC-инвентари сохраняются при наследовании.
- `ecology.ts`: локальные виды и популяции; рост по ёмкости и переход существующего существа по соседней дороге. Драконы не размножаются этим обычным месячным правилом.
- `expansion-commands.ts`: строгие Zod-команды карьеры, дипломатии, владений, строительства, магии, признания наследников и охраны караванов. Все предусловия проверяются до платежей/мутаций. Ожидание и обучение продвигают тот же календарь.
- `expansion-state.ts`: детерминированные значения для старых миров, без расхода RNG. Поля v4: региональные должности/законы/голоса, владения/осады/договоры/верования/организации, потенциал/мана/верование людей, укрепления/оккупация/вид монстров. Учителя — существующие живые взрослые люди с подходящим потенциалом. Никакие новые люди при миграции не создаются.
- `Person.unitClass` позволяет смешивать классы в одном отряде. При отсутствии личного класса используется базовый класс армии. Конница сверяется по живым всадникам, боевые маги расходуют ману и переходят к слабой ближней атаке при истощении.
- `Player.escort` удерживает заранее внесённую отправителем награду. Выплата требует физического совпадения маршрута и доставки; при потере/нарушении сопровождения залог возвращается отправителю.
- `GET /api/history` и `GET /api/admin/people`: постраничный доступ (до 100 записей). WebSocket продолжает передавать ограниченную проекцию. Полные события пока остаются внутри снимка, дисковое архивирование ещё не реализовано.
- Провайдер Director возвращает `{proposal: ...}` по JSON Schema с шестью вариантами. Сервер совместимо принимает прежний прямой объект; окончательное решение всегда принимает `applyProposal`.

Границы: голосуют областные руководители, не все жители; деревни проверяют лояльность/гарнизон после 14 дней, отдельные партизанские отряды не реализованы; две школы магии не обозначают реализацию всех перечисленных в ТЗ школ.

## Военные кампании и сопротивление

`militaryRoute` фильтрует каждое ребро по владению, действующей войне или договору доступа/союза. Государственный марш и ежедневное движение используют эту проверку; истёкший договор останавливает движение. Новые причинные войны используют кампании, старые снимки с пограничными войнами сохраняют прежний путь завершения.

Автономный планировщик раз в неделю выбирает кратчайший доступный маршрут к уже объявленной цели. Мобилизация ограничена живыми работниками, оружием, деньгами и зерном с резервом трёх дней для населения. Армия берёт провиант на путь плюс 70 дней. ID, профессии, казна и груз меняются в одном мире. Армии, которыми управляет игрок, не получают автоматических приказов. Поход заканчивается после перехода цели либо 180 дней; перемирие и временный проход позволяют армиям физически вернуться.

`beginSiege` объединяет существующие армии защитника в реальный гарнизон, сохраняя персональные классы; отряд игрока остаётся отдельно. Блокада учитывает исходно закрытые дороги. Автономный штурм раз в неделю наносит ранения реальным людям с учётом численности и укреплений. При активном тактическом бое ежедневный обработчик эту осаду не изменяет. `defend_siege` добавляет гарнизон на сторону героя; оборонительная победа снимает осаду, отступление сохраняет её. Остатки лошадей сверяются с живыми всадниками.

`Siege.engines` и `Battle.defending` — совместимые необязательные поля v4 (отсутствие означает 0/false); RNG и ID при загрузке не меняются. Команда `siege_engine` валидирует материалы и предел до любого списания. Машины стоят 30 дерева, 10 железа, 5 инструментов и остаются на конкретной осаде.

Оккупационный срок задаёт момент первой проверки, а не безусловную аннексию. Лояльность ≥60 или живой гарнизон прежней державы задерживают переход на семь дней. Пять реальных солдат захватчика при отсутствии защитников снижают лояльность на 5 за проверку. Возврат областного центра отменяет ожидание перехода.
