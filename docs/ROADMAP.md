# Следующие итерации

Развивать текущий runnable проект, не переписывая UI отдельно от симуляции.

1. **Династия и RPG.** Генеалогические/расовые правила, обучение, признание наследника, доли имущества, skills on succession. Приёмка: гибель героя с двумя детьми делит активы и продолжает мир за выбранного допустимого наследника, второй остаётся полноценным NPC.
2. **Политика.** Поведение форм правления, местные лорды, налоги, претензии, восстания и выборы. Приёмка: чрезмерный налог создаёт измеримый дефицит, недовольство, политическую коалицию и реальный переход контроля объектов; нового правителя нельзя получить простой кнопкой без основания.
3. **Кампании и осады.** Армейские маршруты, типы отрядов, снабжение, реальные гарнизоны/запасы, захват центра области и сопротивление деревень. Приёмка: блокада физически прекращает доставку, голод снижает гарнизон и влияет на исход.
4. **Экономика и строительство.** Профессии/цепочки всех ресурсов, караваны разных товаров, частная собственность и основания поселений. Приёмка: добытое железо проходит транспорт и кузню до оружия конкретных солдат.
5. **Магия, религии, существа.** Наследуемый потенциал с редкостью, обучение и цена заклинаний, социальные религии, экологические связи. Приёмка: маг не возникает по команде Director; обучение и способность основаны на данных конкретного жителя.
6. **Director и история.** Остальные whitelist-команды с отдельными validators и tests, cooldown кризисов, артефакты и хроники как предметы. Приёмка: ни одна proposal не может переписать объективные события или изменить числа без легитимной команды движка.
7. **Длительная симуляция.** Population store, календарная очередь, индексы, delta snapshots, история на диске, бюджет WebSocket. Приёмка: benchmark миллионов жителей за многолетний период публикует время шага и память; идентичности и genealogy не теряются.

Для каждого этапа: тест причинности → доменная модель/command → server API → React/Phaser → save migration → тесты и сборка.
